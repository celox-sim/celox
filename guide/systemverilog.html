SystemVerilog Support ​

Celox can simulate synchronous RTL written in SystemVerilog through its Rust API. Enable the systemverilog Cargo feature, supply your source files and choose a top module. The TypeScript package and Vite plugin currently load Veryl only.

The frontend supports a subset of SystemVerilog, including modules, memories, interfaces and two-state or four-state simulation. It shares Celox's backends and runtime with Veryl. See the language reference when checking a particular construct.

Start with a module ​

Enable the feature in your Rust project:

toml
[dependencies]
celox = { version = "*", features = ["systemverilog"] }

Pass the source text and its path to Simulator::from_sv_sources, followed by the name of the top module:

rust
use celox::Simulator;
use std::path::Path;

let source = r#"
    module Counter(input logic clk, input logic rst, output logic [7:0] q);
        always_ff @(posedge clk) q <= rst ? 8'd0 : q + 8'd1;
    endmodule
"#;
let mut sim = Simulator::from_sv_sources(
    vec![(source, Path::new("counter.sv"))],
    "Counter",
)
.build()?;

let clk = sim.event("clk");
let rst = sim.signal("rst");
let q = sim.signal("q");
sim.modify(|io| io.set(rst, 1u8))?;
sim.tick(clk)?; // Reset the counter.
sim.modify(|io| io.set(rst, 0u8))?;
sim.tick(clk)?; // Count one rising edge.
assert_eq!(sim.get(q), 1u8.into());

Supply additional files in the same source list. Each file is a separate compilation unit; choose the top by its SystemVerilog module name.

Choose how to drive the design ​

What your test needsAPI
Set inputs, evaluate logic and advance clock events from RustSimulator::from_sv_sources
Advance simulation time and run supported initial processesSimulation::from_sv_sources
Include both Veryl and SystemVerilog sourcesSimulator::from_mixed_sources

Simulator::tick drives the rising edge of the selected event. Simulation tracks time and runs scheduled edges. Constant initialization applies to both; initial blocks that read design state or call system tasks need Simulation to execute as processes. Timing controls within SV initial blocks remain restricted; see unsupported constructs.

Use .four_state(true) on the builder when your test needs X/Z values. The 4-state guide explains the state model. For time units, $time, $stop and memory loading, see the runtime reference.

What is supported ​

The main supported areas are:

AreaExamples
Design structureModules, hierarchy, parameters, generate blocks, packages, interfaces and modports
DataPacked vectors, multidimensional packed arrays, structs, enums and unpacked memories
RTL processesassign, always_comb, always @*, edge-triggered always and always_ff
ComputationArithmetic, selects, assignment patterns, branches, loops and functions
Simulation helpersImmediate assertions, display tasks, $readmemh / $readmemb, time queries and random numbers

Each area has restrictions. Use the detailed support list to check ports, types, statements or system functions before porting a design.

What is not supported ​

Common reasons a design needs changes are:

  • Class-based verification, concurrent assertions and tasks with timing controls.
  • Latches, multiple drivers and tri-state buses.
  • Non-ANSI module ports, wildcard .* connections, gate primitives and bind.
  • Strings, real, unpacked structs and several interface features.

The complete limitations list includes narrower restrictions and tracking issues. Unsupported constructs produce a diagnostic naming the construct and its tracking issue.

Mix SystemVerilog and Veryl ​

Either language may be the top, and a hierarchy may cross the boundary in both directions. Use Simulator::from_mixed_sources to supply both source lists. Veryl refers to an SV module as $sv::Module; SV uses a Veryl module's emitted name, such as prj_Module.

Interfaces and input / output modports can also cross the boundary. See mixed-language designs for naming, interface parameters and cross-language restrictions.

DPI-C imports ​

Enable sv-dpi to call supported C functions from clocked SV processes. Register functions or shared libraries with dpi_function or dpi_library; these are unsafe APIs because the C signatures must match the SV imports. See DPI-C imports for a complete example and the supported types and call sites.

Find a specific behavior ​

  • Initialization, scopes, variable lifetimes and memory files
  • Time units, precision and time queries
  • Random seeds and reproducibility

SystemVerilog emitted by Veryl ​

The Veryl conformance suite also checks the SystemVerilog emitted by Veryl. Some cases cannot be emitted or have different language semantics; see the remaining exclusions.
