実行の意味論 ​

Celox のクロックを駆動する操作は IEEE 1800 のスケジューリングで定義されて います。イベントベースの Simulator では、ホストの各呼び出しが 1 つの タイムスロットで、その中で決まった SystemVerilog の文が実行されます。Veryl ネイティブテストベンチのクロック・リセットコンポーネントは、決まった SystemVerilog のコードです。そのコードを IEEE 1800 準拠のシミュレータで 実行すると、Celox と同じ値が観測されます。

以下のコードで、s はイベント（クロックまたはリセットのポート）の信号、 A はそのアクティブレベル、I は非アクティブレベルです。A は 立ち上がりエッジのクロックと active-high リセットで 1、立ち下がりエッジの クロックと active-low リセットで 0 です。Veryl の抽象 clock 型と reset 型では、ビルドのクロック種別とリセット種別に従います。

リセットの極性と同期・非同期は設計側の性質で、ここの規則には現れません。 Veryl は always_ff (clk, rst) { if_reset ... } を、非同期 active-low リセットなら always_ff @(posedge clk, negedge rst_n) if (!rst_n) ... に、同期リセットなら always_ff @(posedge clk) if (!rst_n) ... に出力し、 IEEE 1800 のスケジューラが信号の動きだけからそれぞれの振る舞いを作ります。

Simulator API ​

Simulator にはシミュレーション時刻がありませんが、スケジューリングは IEEE 1800 のシミュレーションと同じです。ホストの各呼び出しは 1 つの タイムスロット（IEEE 1800-2023 4.4）です。呼び出しの文はそのスロットで 実行され、スロットはすべての領域が空になるまで進み、次の呼び出しは後の スロットで始まります。呼び出しと呼び出しの間の読み出し（get、 sim.dut.x）は、完了したスロットの状態を見ます。

呼び出しスロットの文
set(x, v)、sim.dut.x = vx = v;
edge(e, Rising)、posedge(e)s <= 1;
edge(e, Falling)、negedge(e)s <= 0;
active_edge(e) / inactive_edge(e)s <= A; / s <= I;
edges([(e1, l1), …, (ek, lk)])s1 <= l1; … sk <= lk;
tick(e)s <= A; そして次のスロットで s <= I;
tick(e, n)tick(e) を n 回
tick_events([e1, …, ek])s1 <= A1; … sk <= Ak; そして次のスロットで s1 <= I1; … sk <= Ik;

ホストは設計内のプロセスではないので、上の表に遅延は現れません。スロットは 設計が 1 つの文に応答する単位です。同じ列を SystemVerilog シミュレータで 実行するには、文を 1 つの initial プロセスに並べ、各文の後に時間精度 1 単位の遅延を置きます。Simulator は遅延を含む設計を受け付けないので、 その単位の長さは観測できません。

ここから次のことが従います。

  • tick はクロック 1 周期です。どちらかのエッジに反応するドメインはすべて 実行されます。イベント自身のドメインはアクティブエッジで、逆エッジの ドメイン（@(negedge clk)、~clk をクロックとするレジスタ）や clk & en のように信号から計算されるクロックは、それぞれが見るエッジで 実行されます。信号は非アクティブレベルで終わります。
  • すでにアクティブレベルにある信号では、s <= A は何も変えないので アクティブエッジは起きません。2 値で 0 から始まる active-low リセットを tick すると、解除されるだけです。リセットをアサートするには negedge(rst) か active_edge(rst) を使います。
  • 1 つのスロットで起動されたドメインは、ノンブロッキング代入と同じく、 スロット前の状態をサンプルしてからまとめて更新します。複数クロックの 同時エッジ（edges、tick_events）では、共有スロットの前の値を互いに サンプルします。レジスタによる分周クロックのように、そのスロット自身が 動かすクロックは、コミットの後にスロット内で立ち上がり、そのドメインも 同じスロットで実行されます。
  • 4 値の設計では、不定レベルはどちらのレベルとしても扱われます。x から 1 は立ち上がりエッジ、x から 0 は立ち下がりエッジです （IEEE 1800-2023 Table 9-2）。

set や sim.dut 経由の書き込みで、イベント信号や、それから計算される クロックを動かしてはいけません。Celox がドメインを実行するのは上の エッジ操作だけです。これらの信号は edge や tick とその派生で駆動して ください。

ホストからのリセット ​

クロック n 周期のリセットは、リセットのアクティブエッジ、クロックの n 回の tick、リセットの非アクティブエッジです。

typescript
sim.activeEdge(rst);
sim.tick(clk, n);
sim.inactiveEdge(rst);

非同期リセットのドメインは最初のスロットで、クロックエッジの前に実行 されます。同期リセットは最初の tick でリセットされます。この列は、後述の テストベンチの rst.assert(n) と同じスロット列です。

複数のクロック ​

tick はそのイベントの 1 周期なので、2 つのクロック入力の位相関係は表せ ません。clk と、その 2 倍の周期をもつ clk_half のように周波数比のある クロックは、edges で瞬間ごとに駆動します。

typescript
sim.edges([[clk, "posedge"], [clkHalf, "posedge"]]);
sim.edges([[clk, "negedge"]]);
sim.edges([[clk, "posedge"], [clkHalf, "negedge"]]);
sim.edges([[clk, "negedge"]]);

または、入力ごとに addClock した timed Simulation を使います。 tick_events([clk, clk_half]) と tick(clk) を交互に呼ぶ方法は、 立ち上がりエッジだけを見るドメインに対してのみ同じ結果になります。 clk_half が次の立ち上がりではなく clk の立ち下がりと同時に立ち下がる からです。

Veryl ネイティブテストベンチ ​

Veryl テストベンチの initial ブロックは SystemVerilog の initial プロセスで、$finish() は $finish です。ホストと違い、これらの プロセスにはシミュレーション時刻があります。以下のコンポーネントは SystemVerilog のコードで、その遅延はテストベンチの時間です。

$tb::clock_gen ​

inst clk: $tb::clock_gen #(period: P); は、イネーブル付きの発振器です。 いずれかのプロセスが clk.next か、このクロックのリセット生成器の rst.assert で待っている間だけ動きます。P の既定値は 2 で、最小値も 2 です。H = ceil(P / 2)、L = floor(P / 2) として:

systemverilog
bit clk = 1'b0;
int unsigned clk_waiters = 0; // clk.next / clk の rst.assert 中のプロセス数

initial forever begin
  wait (clk_waiters != 0);
  clk <= 1'b1;
  #H clk <= 1'b0;
  #L;
end
  • 生成器はイネーブルを再び見る前に必ず 1 周期を終えるので、立ち上がり エッジは、プロセスが待ち始めた時刻と、直前の立ち上がりエッジに P を 足した時刻の遅いほうになります。続けて呼んだ next は途切れず、しばらく 待たれなかったクロックは、次にプロセスが待ち始めた瞬間に再開します。
  • 誰も待っていないクロックにはエッジがなく、そのドメインは実行されません。

clk.next(n) ​

systemverilog
task automatic clk_next(int unsigned n);
  if (n != 0) begin
    clk_waiters++;
    repeat (n) @(posedge clk);
    clk_waiters--;
    #P;
  end
endtask

clk.next() は clk.next(1) です。

  • プロセスは、待っていた n 回目の立ち上がりエッジから 1 周期後、次の 立ち上がりの直前に再開します。そのため、その周期の両エッジの後の状態を 観測します。クロックは Low で、立ち下がりエッジのドメインは実行済みです。
  • クロックはノンブロッキング代入で立ち上がり、同じ時刻に再開した プロセスの実行後に立ち上がります。そのため、2 つの next の間で プロセスが書き込んだ値は、競合なく次の立ち上がりエッジでサンプルされます。 周期の終わりに再開したプロセスがすぐに next を呼べばクロックは 止まりません。プロセスと生成器のどちらが先に動いても、立ち上がりは 同じスロットです。
  • 同じクロックを待つプロセスは同じエッジを数えます。同じ時刻に立ち上がる 周期の異なるクロックは 1 つのノンブロッキング代入領域で更新されるので、 それらのドメインはエッジ前の値を読みます。

$tb::reset_gen ​

inst rst: $tb::reset_gen #(cycles: C) (clk); は、テストベンチの reset 型のリセットネットで、時刻 0 から非アサート状態です。

systemverilog
bit rst = I;

rst.assert(n) ​

P を生成器に渡したクロックの周期として:

systemverilog
task automatic rst_assert(int unsigned n);
  if (n == 0) n = 1;
  rst = A;
  clk_waiters++;
  repeat (n) @(posedge clk);
  clk_waiters--;
  #P;
  rst = I;
endtask

rst.assert() は rst.assert(C) で、C の既定値は 3 です。

  • アサートは、他のテストベンチの書き込みと同じく、プロセスが到達した 時点でのブロッキング書き込みです。非同期リセットのドメインは、クロック エッジなしに、そのクロックが動いているかどうかにかかわらず、その瞬間に 実行されます。同期リセットのドメインは次の立ち上がりエッジでリセット されます。
  • レベルは clk の n 周期保持されます。次の立ち上がりエッジ、または 同じ瞬間の立ち上がりエッジ（クロックはプロセスの書き込み後に立ち上がる ため）から始まる n 回の立ち上がりエッジと、その最後のエッジの後の 1 周期です。どちらの種類のリセットも n 回のリセットエッジを見て、 n + 1 回目のエッジの前に解除されます。
  • プロセスの再開とリセットの解除は、next が再開するのと同じ位相、つまり 最後に待ったエッジから 1 周期後、次のエッジの直前です。その後の書き込みは 競合なくそのエッジでサンプルされ、rst.assert(n); clk.next(m); は n + m 周期です。
  • rst.assert(0) は rst.assert(1) です。アサートしたスロットで解除される リセットは SystemVerilog ではグリッチなので、意味を与えません。

このページが定義するのは $tb::clock_gen、clk.next、$tb::reset_gen、 rst.assert です。他のテストベンチコンポーネント $tb::file と $tb::random はスケジューリングに関与しません。
