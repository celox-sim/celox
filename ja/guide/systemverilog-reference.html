タイミング制御 ​

時間を持つ Simulation では、initial と通常の always のプロセスが中断できます。

制御対応範囲
#delay整数と実数の遅延、#(min:typ:max)（typ の値）、#pkg::D のような package スコープの値、時間リテラル。X / Z の遅延は 0 として扱う
@(...)変数、posedge / negedge / edge、or または , で並べた項目、ビット選択・部分選択・実行時添字の選択、pure な関数呼び出しを含む任意の式、文が読む変数を待つ @* / @(*)
wait (condition)任意の条件。X / Z の条件は偽として扱う
代入ブロッキング代入とノンブロッキング代入。代入先はブロッキング代入と同じで、unpacked 配列の要素や実行時に決まる位置も使えます。ノンブロッキング代入は代入を実行した時点で評価した位置に、そのタイムスロットの NBA 領域で反映します。代入先の範囲外のビットと、X や Z のビットを含む位置には書き込みません

文が読む変数をちょうど並べたセンシティビティリスト（@* が求めるもの、IEEE 1800-2023 9.4.2.2）を持つ always は、always @(a or b) y = a + b; や always @(b, a) y = a + b; のように、 Simulator でも Simulation でも always @* と同様にシミュレーションします。 文にはタイミング制御とノンブロッキング代入を含められません。エッジを持たないそれ以外の センシティビティリストを持つ always はプロセスとして実行します。always @(a) y = a + b; は b だけが変化しても y を更新しません。always @* として扱うと他の論理と組み合わせループを作るリストも プロセスとして実行します。フリップフロップの形をしていないエッジ駆動の always も同様です。 選択や式のエッジ（@(posedge v[0])、@(posedge (a & b))）、edge、エッジと並んだエッジなしの項目、 複数ビットのエッジ信号（最下位ビットでエッジを判定）、本体がどれも非同期リセットとして判定しない 複数のエッジを持つものがこれに当たります。この形でなければならないのは always_ff だけです。 Simulator はプロセスを実行しないため、このようなデザインでは SimulatorErrorKind::ProcessRequiresSimulation でビルドに失敗します。Simulation を使うか、 always @* / always_comb で記述してください。

時間待ちを含む task ​

initial と通常の always から、#delay・@(event)・wait (condition) を 含む task を呼び出せます。task のネストも可能です。呼び出しは呼び出し元の状態機械に インライン展開されます。エッジ待ちの always は task の完了後に次のエッジを待ちます。 時間待ち task を呼ぶ always @* もプロセスとして実行します。文が読む変数（task の引数を含み、 task 本体が読む変数は含まない）の変化を待ち、task の実行中に起きた変化は見送ります。 function・always_comb・always_latch・always_ff からの時間待ち task 呼び出しは拒否します。

automatic な引数とローカル変数は呼び出しごとに独立し、中断中も保持されます。 module 内の static task の引数は共有されます。input／inout は呼び出し時にコピーされ、output／inout は task 終了時にコピー戻しされます（IEEE 1800-2023 13.3–13.3.2）。時間待ち task の static ローカル宣言は未対応のため、automatic を使ってください。 package／$unit の static 引数を持つ時間待ち task と、static task 引数を読む wait 条件は、 共有ストレージと変更通知に対応するまで拒否します。 イベント式の制約は、プロセスに直接記述するイベント待ちと同じです。

スコープ変数の乱数化 ​

randomize(a, b) と std::randomize(a, b) は、制約なしで packed 変数全体を乱数化します。 符号付きベクタと packed struct を含め、Celox が扱える幅で各ワードに0／1の乱数を設定し、 成功値の1（signed int）を返します。引数なしの場合は変数や乱数列を変更せず成功します。 プロセスごとの永続的な乱数列を使い、文の実行順序と短絡評価に従います （IEEE 1800-2023 18.12）。

64ビット以下のスカラーenumにも対応し、既知の宣言値だけから抽選します。 型エイリアス、負数、飛び飛びの値、整数との引数混在を扱えます。enumにもプロセス単位の 乱数列・短絡評価・チェックポイント復元が適用されます。

with 制約、値域が未対応または未解決のenum、unpacked 配列、net、定数、 select・連結式の引数は未対応として拒否します。

クラスの乱数化 ​

object.randomize() は有効な rand プロパティを乱数化し、成功値の1（signed int）を返します。 制約のないクラスで、スカラーenumを含む64ビット以下の2値整数型に対応します。 enumは宣言された値だけから均等に抽選し、飛び飛びの値や負数にも対応します（18.3、18.4.1）。 値が未解決またはX/Zを含むenum、列挙子の範囲指定は乱数化に未対応です。 継承したプロパティも対象になり、基底型のハンドルを通した呼び出しでも、実際のオブジェクトの クラスと pre_randomize() / post_randomize() を使います。子クラスでフックを定義すると 親のフックを置き換えるため、親の処理も必要なら super.pre_randomize() などを明示的に呼びます （IEEE 1800-2023 18.6.2）。フックは引数なし・非static・非virtualの関数に限ります。 クラス内では randomize() や this.randomize() と書けます。

object.member.rand_mode(0) で乱数プロパティを無効化し、rand_mode(1) で有効化します。 引数なしの object.member.rand_mode() は現在のモードを signed int で返します。 設定側の引数型は bit です。object.rand_mode(bit) は継承分を含む全乱数プロパティに適用します。 初期状態はすべて有効で、aliasは同じモードを共有します（18.8）。

object.randomize(x, y) はその呼び出しに限り対象を指定します。対応型なら rand でない プロパティも指定できます。名前は呼び出し元ではなくreceiverのクラスで解決し、式やアクセス権のない メンバーは拒否します。一時モードはpreフックの前に設定し、postフックの後に復元します。 フックから一時モードを参照・変更できます。randomize(null) は乱数生成や代入を行わずフックを 呼びます（18.11）。この形式でも制約付きクラスは未対応です。

オブジェクトごとに独立した乱数列を持ち、生成元のプロセスから初期シードを取得します。 object.srandom(seed) で32ビットのシードを設定でき、チェックポイントは乱数状態とモードを保持します （18.13.3、18.14.3）。具体的な乱数列は処理系に依存します。 randc は1〜8ビットの2値整数と、宣言値が256個以下のスカラーenumに対応します。 各プロパティは全値を重複なく一巡してから次の循環に進みます（18.4.2）。継承、 rand_mode、引数による対象選択とチェックポイント復元にも対応します。無効化中は 循環を進めず、srandom は消費済みの値を保持したまま乱数生成器を再シードします。

制約、with、上記の上限を超える randc、staticな乱数プロパティ、配列・オブジェクト・文字列の 乱数化は未対応です。実際の子クラスに制約がある場合は、親のプロパティだけを乱数化せず拒否します。 null を通した呼び出しは実行時エラーです。

時間リテラルによる遅延 ​

遅延制御の時間リテラルは #5ns、#(2.75ns)、#40ps など、fs から s の6単位に 対応します。宣言スコープの時間精度で丸めてから scheduler の tick に変換します （5.8、3.14.1）。#1.5 や #r などの実数の遅延も同様に丸め、ちょうど中間の値は 0 から遠い方に 丸めます（6.12.1）。負の遅延は2の補数として待ち（9.4.1）、NaN の遅延は 0 として扱います。

未対応の構文 ​

未対応の構文は、無視せずに、その構文名を示す Unsupported エラーを返します。エラーには その構文を追跡する issue の番号が含まれます。専用の issue がない構文は、フロントエンドの ロードマップ #88 を指します。

  • 対応範囲外のクラスの機能：クラスハンドル以外の変数への $cast、interface クラスの typedef とパラメータ、package 内で宣言したクラス、パラメータ付きクラス、名前付きのコンストラクタ引数、浅いコピー（new h）、4 値・real・配列・64 ビットを超えるプロパティ。時間待ちを含む task の static ローカル宣言、再帰呼び出し、ref 引数。
  • interface のポート、inout / ref / 式を使う modport、virtual interface など。 interface 自体と入れ子の interface は対応しています。型パラメータはインスタンスごとに解決し、modport ポート経由でも伝搬します。 再帰する特殊化と64段を超える入れ子は拒否します。細かな制約は英語版の一覧を参照してください。
  • 振る舞い記述・検証向けの構文：final、代入内のタイミング制御（a = #1 b）、遅延付き継続代入（#444）、 named event と ->、fork / join、wait fork / disable fork、並行アサーション、force / release。
  • プロセス内のタイミング制御：iff 修飾（#1444）、 イベント式内の impure な関数呼び出し、 static task 引数を読む wait 条件とイベント式。
  • always_latch 内のノンブロッキング代入（#431）。対応するラッチではブロッキング代入を使用してください。
  • always_comb の暗黙のラッチ推論はデフォルトで拒否します。celox.toml の [diagnostics] で inferred_latch = "warn" または "allow" を指定すると許可できます。通常の always @* と明示的な always_latch にはこの設定は不要です。
  • ポートとインスタンス：non-ANSI 形式のポート式（module m({a, b}, c[3:0], .p(d)) など、#1953）、ref ポート（#427）、 ワイルドカード接続 .*（#442）、ゲートプリミティブ（#457）、bind。
  • 宣言：interface 配列のメンバーの変数宣言の初期化子、ANSI ポートの既定値、tagged union、unpacked union、packed union の assignment pattern、ドライバを持たない内部ネット（#460）、unpacked 構造体、real。
  • 順序回路のプロセス：イベントリストの iff 修飾（#452）、および always_ff での 単純な信号以外のエッジオペランド（#464）、複数ビットのエッジ信号、 非同期リセットを持たない複数のエッジ。
  • 組み合わせ回路のプロセス：always_comb 内のノンブロッキング代入（#453）。
  • ループ：手続き的なループの展開は 10,000 回までです。反復回数が実行時に決まる組み合わせ 回路のループは、カウンタ形式の for である必要があります。loop-generate は 10,000 回を 超えると拒否し（#448）、ビット演算の複合代入による genvar の更新は拒否します （#455）。
  • 式：ストリーミング連結（#447）、パラメータ式での リダクション演算子（#456）。
  • システムタスクとシステム関数：Celox は IEEE 1800-2023 が定義するすべての名前を、 附属書 D の任意のものも含めて知っています。呼び出した位置で対応していないもの（$fgets など）は、 使われていないパラメータや関数本体の中を含め、書かれた 場所にかかわらず名前を示して報告します。システムタスクでもシステム関数でもない $ 名、 引数の数が誤っている呼び出し、既定値のない引数の省略、値として使ったタスクはエラーです。
  • DPI-C の対応範囲を超える機能と DPI export、複数のドライバを持つネット（トライステートバスを含む）、トップモジュールの inout ポート、階層参照。

実行時の挙動 ​

上限なしのパラメータ ​

$isunbounded(P) は、値パラメータが $ の場合に1、それ以外では0を1ビットの符号なし値として返します。$ は別のパラメータへの代入やインスタンスのパラメータ上書きでも保持されます（IEEE 1800-2023 6.20.7、20.6.3）。

文字列 ​

string 型の変数はシミュレータのヒープ上の文字列への参照を持ちます。代入、等値比較、値の変化の検出は 32 ビット整数と同じコストで、文字列の中身を読む・作る演算だけがランタイムを呼び出します。文字列はタイムスロットの間と各 tick の後に回収されます。IEEE 1800-2023 6.16 のとおり、文字列にするときに NUL バイトは取り除かれ、文字列へ代入・キャストした整数値は最上位のバイトから並びます。

未対応：$sformat / $sformatf、atoreal / realtoa、$value$plusargs・ファイル I/O・DPI-C の文字列引数、VPI・VCD 出力・TypeScript API での文字列値。

クラス ​

クラス型の変数はシミュレータのヒープ上のオブジェクトへのハンドルを持ち、コンストラクタを呼ぶまでは null です。文字列と同じく、ハンドルのコピーと比較は 32 ビット整数と同じコストで、プロパティの読み書きとオブジェクトの生成だけがランタイムを呼び出します。どの変数・オブジェクトからも参照されないオブジェクトは、タイムスロットの間と各 tick の後に回収されます。メソッドは呼び出したオブジェクトを受け取るので function でも task でもよく、呼び出しは変数のクラスのメソッドに結び付きます（IEEE 1800-2023 8.6）。virtual メソッドの呼び出しは、代わりにオブジェクトのクラスの override を実行します。ただし super.m(...) は基底クラスの実装を実行します（8.15、8.20）。override はオブジェクトのクラスで選ぶので、ランタイムの呼び出しが 1 回増えます。null を通したプロパティの読み書きやメソッド呼び出しは実行時エラーです。抽象クラスの生成と、pure virtual メソッドを実装しないクラスはエラーになります（8.21）。interface クラスを実装するクラスは、そのメソッドをすべて同じ戻り値型で実装するか、抽象クラスなら pure として宣言し直します（8.26）。interface クラスのハンドルを通して呼んだメソッドは、オブジェクトのクラスの実装を実行します。

ハンドルは、そのクラス・基底クラス・実装する interface クラスの変数に代入でき、それ以外のハンドルの代入はエラーです（IEEE 1800-2023 8.16、8.26.5）。$cast(dest, source) は、オブジェクトのクラスが dest のクラスを継承または実装するハンドルか null を代入して 1 を返します。それ以外では dest を変えずに 0 を返し、タスクとして呼んだ場合はエラーを報告します。どちらも他方を継承しないクラスどうしの $cast は、ソースが interface クラスでない限り常に失敗します（8.16）。

コンストラクタは、まず super.new(...) または extends 節の引数で基底クラスのコンストラクタを呼び、次に自クラスが宣言するプロパティの初期値を設定し、最後に本体を実行します（IEEE 1800-2023 8.17）。static プロパティはクラスを宣言したモジュールの変数なので、モジュールのインスタンスごとに 1 つずつあります。

チェックポイントはオブジェクトを保持します。状態ファイルは文字列を記録しますがオブジェクトは記録しないため、オブジェクトを持つ変数があると状態ファイルの保存は失敗します。

インスタンス配列の要素 ​

要素は宣言どおりの添字で参照します。Child u[3:2](...) の u[3] には child_signal(&[("u", 3)], "y") や dut.u[3] で届き、添字は InstanceHierarchy::index にも入ります。負の境界を持つ配列は拒否します。

範囲外の選択 ​

ベクタの端を越える実行時の選択は、足りないビットを X（2 値シミュレーションでは 0） として読み、書き込みは存在するビットだけを更新します。ベクタから一部はみ出す定数の パートセレクトへの書き込みも、手続き代入・継続代入のどちらでも内側のビットだけを更新します。 logic [7:0] q への q[9:6] = v は v[1:0] を q[7:6] に書き込みます。ベクタから 完全に外れた書き込みは何もしません。このような定数のパートセレクトの読み出しと、配列要素や 内側の packed 次元の宣言範囲を越える定数のパートセレクトへの書き込みは拒否します （#88）。

ワイルドカード比較 ​

casez、casex、inside、==? は、定数パターンの ?、x、z ビットを、2 値・4 値のどちらのシミュレーションでも尊重します。

package ​

package はそれぞれ独立したスコープとして 1 回だけ解析し、名前は IEEE 1800-2023 26.3 の規則で解決します。p::x は package p の項目を指すため、複数の package、または package と モジュールに同名の項目があっても衝突しません。import p::x; で見えるのは x だけです。 import p::*; では、スコープ自身の宣言が package の同名の項目を隠し、2 つの wildcard import の package が宣言する名前は、参照したときだけエラーになります。generate ブロック内の import は、そのブロック （と内側のブロック）でだけ名前を見えるようにし、モジュール自身の宣言や import より優先されます。package の関数の中の名前は package の中で解決します。package の変数は、それを使うすべてのモジュール（Veryl からインスタンス化した SystemVerilog モジュールを含む）で共有される 1 つのオブジェクトで、初期化子も反映します。 sim.signal("p::v") で参照できます。1 つの package 変数を複数のドライバが書く設計は、書き込む モジュールのインスタンスをすべて数えて拒否します。package 変数のクロック・リセットとしての使用、定数でない package 変数の初期化子、 package の net は未対応です（#1146）。export 宣言（26.6）は、import した宣言をその package を import する側から見えるようにします。export p::*; が export するのは package が p から実際に import した名前だけです。export を経由した import は元の宣言を指すため、 2 つの経路で同じ宣言を import しても曖昧になりません。q::x は q が x として export する宣言も指します。

コンパイル単位 ​

ソースファイルはそれぞれ独立したコンパイル単位です（IEEE 1800-2023 3.12.1）。 モジュールや package の外にあるパラメータ、型、サブルーチン、変数、import は、そのファイルのモジュールを 囲むスコープ $unit になります。モジュールからは、自身の宣言と import の次に、それより前に宣言された コンパイル単位の項目と import、およびコンパイル単位のすべてのサブルーチンが見えます。$unit::x は コンパイル単位の項目 x を指します。コンパイル単位の変数は、そのファイルのモジュールが共有する 1 つの オブジェクトで、package 変数と同じく $unit::v という名前になります。これを宣言できるソースファイルは 1 つだけです。コンパイル単位での DPI import は未対応です。

ブロックローカル変数 ​

ブロックローカル変数は、always_comb と always_ff で字句スコープを持ちます。 モジュールの信号と同名の変数や、別のブロック・プロセスでの同名変数を扱えます。

packed untagged union ​

hard packed untagged union のメンバーは、同じビットベクタを共有します。 全メンバーの幅が一致する必要があります（IEEE 1800-2023 7.3.1）。 union soft / union soft packed は幅の異なるメンバーを許容します。 全体の幅は最大メンバーの幅となり、各メンバーは最下位ビットから配置されます。 小さいメンバーへの書き込みでは残りの上位ビットを保持します。 packed union と packed 構造体の入れ子にも対応します。

systemverilog
union soft packed {
    logic [15:0] word_value;
    logic [7:0] byte_value;
} data;
// data.word_value = 16'h1234 の後で data.byte_value = 8'hab とすると data = 16'h12ab。

union 全体の演算は宣言時の符号指定に従います（既定は unsigned）。 bit / logic 混在時は 4-state の領域を共有し、2-state メンバーを 読み書きする際には X/Z を 0 に変換します。 tagged union と unpacked union は未対応です。

名前付きサブルーチン引数 ​

名前付きサブルーチン引数は仮引数の名前で束縛し、入力の評価と出力のコピーアウトは ソースに書かれた順序で行います。式と文のどちらでも、ANSI宣言で既定値を持つ引数を省略できます。 既定値は使うときだけ、サブルーチンを宣言した外側のスコープで評価します（IEEE 1800-2023 13.5.3）。 パラメータ初期値・範囲・generate条件の定数呼び出しも仮引数名で束縛し、generate内の宣言は自身のシグネチャを使います。 選択の添字での副作用を伴う名前付き呼び出しは拒否します。

型付きパラメータパターン ​

型付きパラメータパターンは呼び出し元の型で変換し、幅・符号・4-state の値を保持します （IEEE 1800-2023 10.9、6.20.2）。packed 値はビット列として渡すため、子の構造体の メンバー名やフィールド分割が異なっても扱えます。型付き scalar パターンは、既定値が 通常の値であるパラメータも上書きできます。unpacked パターンは配列の位置と形状を保持します。

ラッチ ​

明示的な always_latch と通常の always @* は、ブロッキング代入による値の保持に対応します。 SystemVerilog と Veryl の always_comb の不完全な代入は、共通の [diagnostics] 設定 で inferred_latch = "warn" または "allow" を指定すると値を保持します。既定は error です。 Rust の .allow_inferred_latches(true) と JavaScript の allowInferredLatches: true も利用できますが、明示した診断設定が優先されます。 通常の eval_comb と initial テストベンチの両方で 使用でき、ゲートが開いている間はデータの変化が出力に伝わり、閉じると直前の値を保持します。 4状態モードの未初期化ラッチは X で始まります。手続き型 if の条件が X または Z の場合は、真側を実行しません。

always_comb と always_latch は時刻 0 にも一度実行します。always @* は 感度リストの入力変化を待ちます。これには initial ブロックや連続代入による変化も含みます。 同じ入力で eval_comb を繰り返しても再実行しません。always_comb と同様に、書き込む式は always_latch の 感度リストから除外します（IEEE 1800-2023 9.2.2.2、9.2.2.3）。プロセス間の フィードバックには従来どおり明示的なループ設定が必要です。このオプションは、 明示的な算術フィードバックに対する Veryl アナライザーのエラーを抑制しません。 bus[0] のような選択を読む場合、always @* は変数全体を監視し、 always_comb と always_latch は静的に特定できる最長の接頭部を監視します。 後者は呼び出した関数本体の読み取りも含みますが、task 呼び出しは引数の式だけが 感度に寄与します（IEEE 1800-2023 9.4.2.2、9.2.2.2.1）。 ノンブロッキング代入（<=）には NBA スケジューリングが必要であり、推論を許可しても未対応です。

イベント待ちとレベル待ち ​

  • イベント制御は、開始した後に起きた変化を待ちます（IEEE 1800-2023 9.4.2）。 a = 1; @(a ^ b); の a への書き込みはこの待ちのイベントにならず、 その後に a か b が変化したときに再開します。 Icarus 13.0 は先の書き込みで起床し、Verilator 5.052 は Celox と同じ結果になります。
  • 複数ビットの式の posedge / negedge は最下位ビットで判定します（Table 9-2）。 @(posedge v) は v[3] を無視し、@(posedge v[3]) は v[3] に従います。 X / Z を経由する遷移も同表に従い、0 から x は posedge です。
  • 継続代入、組み合わせ回路のプロセス、イベント式は、書き込んだプロセスがタイミング制御に 達するか終了した時点でその書き込みを参照します。b = 1; a = 1; の後でも a ^ b は 変化しておらず、パルス a = 1; a = 0; は @(a) を起こしますが @(a ^ b) は起こしません。 パルスを見せるには書き込みの間に #0 を入れてください。この順序は IEEE 1800-2023 4.7 で 許されています。Icarus は書き込みごとに式を評価します。
  • always_comb、always @*、エッジで起動する always、always_ff の1回の評価が書いた値は、 後の書き込みで上書きされるものも含めてすべて待ち側から見えます。a が 1 のとき、 y = 0; if (a) y = 1; は @(y) を起こします（IEEE 1800-2023 4.3、9.4.2）。ノンブロッキングの 更新は NBA 領域で発行順に適用し、それぞれが1回の更新です（10.4.2）。子モジュールの出力ポートは 親のネットへの継続代入なので（23.3.3）、親の待ちは前の項目と同じく確定した値だけを見ます。 Verilator 5.052 は評価の最終値だけを見ます。Icarus 13.0 はポートを通したパルスも見ます。

変数の寿命 ​

変数の寿命は IEEE 1800-2023 6.21 に従います。クラス外のプロセスのブロック、関数、タスクの中で宣言した 変数は、その変数自身、そのサブルーチン、またはそのモジュール（module automatic）が automatic と宣言されていない限り static です。クラスメソッドの寿命は automatic です（8.6）。 ブロックの static なローカル変数は、ブロックの実行をまたいで値を 保持し、初期化子は時刻 0 に 1 回だけ実行します。always_ff 内の int count; count++; は数を数えます。 automatic なローカル変数は、ブロックに入るたびに初期化します。どの経路でも読む前に書き込むため、入った 時点の値が読まれない static なローカル変数は、どちらでも同じ動作です。static なローカル変数は値を保持する ため、一部の経路でしか書き込まない always_comb のローカル変数はラッチになり、ほかの暗黙のラッチと同じく inferred_latch の緩和が必要です。

関数の static ローカル変数と戻り値は、呼び出しをまたいで値を保持します（13.4.2）。 スカラーの real と packed／unpacked な整数の保存領域に対応しています。automatic 関数内で 明示的に static とした変数も共有され、automatic 変数は呼び出しごとに初期化されます。 static な output 引数も、代入しない経路では以前の値を保持します。保持が必要な領域は呼び出し位置と 時間待ちプロセスの間で共有され、モジュール内の領域はインスタンスごとに独立します。 宣言の初期化子は、関数が未呼び出しでも時刻 0 に一度だけ実行します。状態を保持する関数を 呼び出す初期化子は、初期化プロセスを実行する Simulation または native testbench が必要です。 定数関数としての呼び出しは 毎回新しい値を使い、実行時の状態に影響しません（13.4.3）。

値を保持する task ローカル変数と、定数でない static 初期化子は引き続き未対応です。 これらには automatic を指定してください。package 関数の状態には、複数の手続きドライバーに関する 既存の package 変数の制約が適用されます。既定の寿命（interface automatic）が 使用先のモジュールと異なる interface は拒否します。

実行時のループ ​

反復回数が実行時の値で決まる always_ff 内のループは、生成コード内の ループとして実行します。進まなくなったループは、ループ変数を示す実行時エラーを報告します。

文として呼び出したシステム関数 ​

文として呼び出したシステム関数（$countones(f(a)); など）は、式の中の同じ呼び出しと 同様に検査・評価し、値を捨てます。$bits と $size は被演算子を評価しません。

重大度タスクと報告 ​

$info、$warning、$error、$fatalは、fail アクションのない assert / assume の既定の $error も含めて、RuntimeEvent::Report として報告します（IEEE 1800-2023 20.10）。Report は重大度、メッセージ、`__FILE__ と `__LINE__ が示す呼び出しのファイルと行、報告した スコープを持ちます。即時アサーションのアクションブロックからの報告は、そのアサーションも示します。 文ラベル、assert / assume / cover の別、pass と fail のどちらのアクションから出たかです。 アクションブロックが呼ぶサブルーチン内の重大度タスクは、アサーションに結び付けません。time は drain のコンテキストが与える時刻で、VPI ホストはコールバックごとに与えます。Simulation::set_fail_on の設定中は、報告が出たタイムステップの時刻です。Report::render は、 VPI ホストと celox コマンドが表示する形に整形します。celox の実行を失敗にするのは $error と $fatal だけで、$fatal はさらにシミュレーションをエラーで終了します。

遅延付きアサーション ​

assert #0、assume #0、cover #0 とそれぞれの final 形のアクションは、プロセスの遅延 アサーション報告キューで待ちます（IEEE 1800-2023 16.4）。引数はアサーションを実行した時点で 評価します。プロセスはフラッシュ点でキューを空にします（16.4.2）。

  • タイミング制御を含むプロセスは、イベント制御や wait から再開するたびに。遅延からの再開は フラッシュ点ではありません。
  • エッジで起動する always / always_ff プロセスは、実行するたびに。
  • always_comb、always_latch、組み合わせ回路として扱う always（タイミング制御が先頭の イベント制御だけのもの）は、再実行するたびに。

タイムスロットが終わると、まだ待っているアクションを #0 のもの、final のものの順に実行します。 遅延付きの $fatal はそこでシミュレーションを終了します。モジュール直下の遅延付きアサーションは、 always_comb に入れた同じアサーションです（16.4.3）。アクションは表示タスクか重大度タスクの 呼び出し 1 つで、ユーザーのサブルーチンや複数の文は拒否します。Simulator では呼び出し 1 回が タイムスロットで、組み合わせ回路が落ち着いたときやドメインを実行したときにアクションが成熟します。

定数関数 ​

定数関数は、呼び出す表示タスクと重大度タスクを無視します。

$readmemh / $readmemb ​

$readmemh / $readmemb は、デザインのコンパイル時にファイルを読みます。ファイルが ないか不正な場合は MemoryFile エラーです。always_ff では起動のたびにファイルの各ワードを 書き込み、initial では初期状態の一部になります。明示した範囲はどちらの向きにも読み込み、 ファイル中の @ アドレスは配列の絶対インデックスです。要求範囲外のアドレス指定はエラーです。 アドレス指定がなくワード数が範囲と合わない場合はコンパイル警告（Simulator::warnings()）に なり、余ったワードは無視され、足りない分のメモリは変わりません。

バイナリ入力 ​

$fread はバイト列をビッグエンディアン順で packed 整数または1次元の静的な 整数メモリへ読み込みます（IEEE 1800-2023 21.3.4.4）。メモリは既定で最小の 添字から昇順に読み込み、開始位置と要素数を省略可能な引数で指定できます。 packed 整数ではこれらの引数を無視します。部分的な読み込みでは、入力を 受け取らなかったビットとその X/Z を保持します。戻り値は読み込んだバイト数、 I/O エラー時はゼロです。

バイト入力とファイル位置 ​

$fgetc(fd) は次のバイトを0〜255の整数で返し、EOF またはエラーでは -1 を返します。 $ungetc(character, fd) はファイルを書き換えずに1バイトを戻し、成功時0、失敗時 -1 を 返します。pushback は1バイトに対応します。$feof(fd) は以前の読み取りで EOF に 達したかを調べます。最後のバイトを読んだだけでは EOF になりません。成功した pushback と位置変更は EOF を解除します。

$ftell(fd) は pushback を考慮したバイト位置を返し、エラーまたは符号付き32ビットの 範囲を超える位置では -1 を返します。$fseek(fd, offset, operation) は符号付き32ビットの offset を使い、先頭（0）、現在位置（1）、末尾（2）を基準に移動します。$rewind(fd) は 先頭に戻します。位置変更は成功時0、失敗時 -1 を返し、成功すると pushback を破棄します。 $fflush(fd_or_mcd) は指定した出力先を、$fflush() は開いている全ファイルを flush します。 無効な flush descriptor は実行時エラーです。これらは時間付き Simulation で実行し、 入力と位置変更には file descriptor を使います。

書式付き入力 ​

$sscanf(source, format, outputs...) と $fscanf(fd, format, outputs...) は 整数の %d、%h / %x、%o、%b、%c と実数の %e / %f / %g 変換、 数値フィールド幅、代入抑制、 リテラル照合と空白を扱います（IEEE 1800-2023 21.3.4.3）。入力と書式には 文字列リテラルまたは packed 整数を使用できます。戻り値は代入した出力の数で、 照合できなかった出力は保持します。実数変換は real、realtime、shortreal に対応し、 符号・小数点・指数部を扱います。shortreal は直接 binary32 に丸め、オーバーフローは 符号付き無限大となり、負のゼロも保持します。符号だけの入力や不完全な指数部は 出力を変更せず失敗します。整数変換には整数、実数変換には実数の宛先が必要です。 文字列出力の %s、時間倍率を扱う %t は未対応です。 両関数とも timed Simulation で実行します。 $sscanf はチェックポイントに対応し、外部ファイルを使う $fscanf は拒否します。

実行時のファイル出力 ​

$fopen、$fclose、$fdisplay / $fwrite とその b / o / h 形は、 時間を持つ Simulation で実行します（IEEE 1800-2023 21.3）。引数が1個の $fopen は multichannel descriptor を返し、OR で複数の出力先を選べます。 ビット0は標準出力です。モードを指定すると file descriptor を返します。 閉じたチャネルは再利用され、オープン失敗は0を返します。無効な descriptor や 書き込み失敗は実行時エラーです。ファイル名とモードは文字列リテラルまたは 整数の packed 文字列を指定できます。パスは UTF-8 に限定し、相対パスはホスト プロセスの作業ディレクトリを基準とします。動的な string 値は未対応です。

$writememh / $writememb は呼び出し時点の静的 unpacked 配列を、既存ファイルを 上書きして出力します（21.5）。実行時の開始・終了アドレスで順方向・逆方向を 指定でき、範囲外は実行時エラーです。X/Z を保持し、アドレス指示子は出力しません。 動的配列と連想配列は未対応です。既存の $readmemh / $readmemb は引き続き コンパイル時に読み込みます。

これらを直接またはサブルーチン経由で呼ぶエッジプロセスには Simulation が必要で、 Simulator のビルダーはエラーを返します。組み合わせプロセスからの呼び出しは未対応です。

集約型の定数パラメータ ​

集約型の定数パラメータ（unpacked 配列や、パターンで与える packed 構造体）は、 シミュレーション開始時から値を保持する変数です。エラボレーション時の定数が必要な場所では 使えません。

シミュレーションの一時停止 ​

initial ブロックの $stop はシミュレーションを一時停止します（IEEE 1800-2023 20.2）。 Simulation::step と run_until は停止した時刻で戻り、is_stopped() が真になります。 その時刻の他のプロセスは待機し、次の呼び出しでループや関数の中も含めて $stop の 直後から再開します。停止した時刻の処理は、停止前にプロセスが起こしたエッジも保ったまま 再開します。停止中はチェックポイントと状態ファイルを作れません（CheckpointError::Stopped）。 always 系のプロセスでは、$finish が RuntimeEvent::Finish に なるのと同様に RuntimeEvent::Stop として報告します。診断レベルの引数では何も 表示しません。VPI ホストのように対話モードを持たないバッチ実行では $stop で終了します。 program（IEEE 1800-2023 24 章）はリーフモジュールと同じく宣言・インスタンス化します。 その initial 手続きはリアクティブ領域セットで実行します。開始、# 遅延後の再開、 イベント制御での起床は Reactive 領域、#0 からの再開は Re-Inactive 領域で行い、 ノンブロッキング代入は Re-NBA 領域で更新します（4.4.2.6〜4.4.2.8、24.3.1）。 リアクティブ領域セットはタイムスロットのアクティブ領域セットが空になってから実行し、 それが起こした設計側の動作は再びアクティブ領域セットで実行します（4.5）。そのため program は、ノンブロッキング更新とそれを受ける論理が落ち着いた後の設計を読みます。 program の手続きが呼ぶサブルーチンはその手続きの領域で実行します（24.5）。 設計のプロセスはコンパイル済みスケジューラのまま、program の手続きは参照スケジューラで実行します。 すべての program のすべての initial 手続きが終わると、暗黙の $finish でシミュレーションを 終了します（24.3）。program 内の always 手続きと、モジュール・インターフェース・program の 宣言やインスタンスは名前を示して拒否します。 未対応: program 内の連続代入は Reactive 領域ではなく設計の組み合わせ論理として評価します。 program の書き込みが駆動する設計の連続代入と組み合わせ論理は、Icarus・Verilator・xezim と同じく リアクティブ領域セットの実行中に落ち着くため、#0 の後に再開した program はその新しい値を読みます。 4.5 ではリアクティブ領域セットが空になってから評価します。 モジュール内に入れ子の program と無名 program は拒否します。どのモジュールからも インスタンス化されない program は、設計のトップモジュールと並ぶ暗黙のトップにはなりません。

$exit は、program の initial 手続きのスレッドから呼ぶと、その program インスタンスの すべての initial 手続きを終了し（24.7）、program の手続きが残らなければシミュレーションも 終了します。それ以外からの呼び出しは 24.7 の規定どおり無視し、 その呼び出し位置でコンパイル警告（Simulator::warnings()）を出します。モジュールの定数関数内の呼び出しも同様です。 関数宣言内の呼び出しは、その関数を使わなくても警告します。定数評価が実行したかどうかには依存しません。

実行時 I/O と plusargs ​

initial やエッジで起動する always / always_ff と、そのサブルーチンからの ホスト I/O には Simulation::from_sv_sources を使います。組合せプロセスからは 未対応です。時間付き実行が必要なエッジプロセスを Simulator で構築するとエラーになります。

引数は .plusargs(["+COUNT=12", "+TRACE"])、または celox run の + 引数で順序を保って渡します。 $test$plusargs は前方一致で検索し、$value$plusargs は整数変換と packed 整数変数への %s を扱います。最初に一致した引数を使い、未一致の場合は書き込み先の値を保持します。 real 変換と動的 string は未対応です。

ファイル descriptor とメモリ書き出しは実行時のファイル出力を参照してください。

VCD 制御の記録開始は、その時刻の状態が確定した後です。 ファイル I/O または SV からの VCD 制御を含むデザインでは、ホスト側の状態を保存できないため、 checkpoint と状態ファイルの保存・復元はエラーになります。

$dist_uniform(seed, start, end) は Annex N の一様分布を使い、整数の seed 変数を更新します。 両端を含み、境界が同じ値か逆順なら seed を進めず start を返します。

$dist_normal、$dist_exponential、$dist_poisson、$dist_chi_square、 $dist_t、$dist_erlang は時間付き Simulation のプロセスとそのサブルーチンで Annex N の分布を使います。引数と戻り値は符号付き32ビット整数です。 整数の inout seed は int に変換し、添字付き要素の場合も一度だけ書き戻します。 指数・Poisson分布の mean、カイ二乗・t分布の自由度、Erlang分布の両引数は正値が必要です。 不正な値は seed を更新せず実行時エラーとして診断します。正規分布の mean と標準偏差は 任意の整数を受け付けます。SV の real 型は必要ありません。seed はデザインの状態なので、 checkpoint の復元で乱数列を再現できます。

時刻と精度 ​

$timeunit と $timeprecision は秒を基準とする指数を32ビットの符号付き整数で 返します（IEEE 1800-2023 20.4.1）。現在の時間スコープ、$unit、$root、 別ファイルを含むスカラーのモジュールインスタンス階層を解決します。 timeunit、timeprecision、先行する timescale、resetall の優先順位は 3.14.2.3に従い、デフォルトは1 ns / 1 psです。グローバル精度には、 インスタンス化されていない定義も含め、すべての精度宣言とディレクティブの精度を 使用します（3.14.3）。インスタンス配列の選択とgenerate階層は、展開後の階層検索が 必要なため、現在は未対応として診断します。

時間単位と精度は、他のスコープ項目より前で別々に宣言でき、同じ値の宣言は 後でも繰り返せます。明示指定・継承による設定とデフォルトがデザイン内で混在する 場合は診断します（3.14.2.3）。モジュール定義とパッケージは、同名でもそれぞれの 時間単位と精度を保持します（3.13）。同名のモジュールがインスタンス化されていても、 パッケージ名による問い合わせを解決します。ルートを含む階層インスタンスが見つかった 場合は、同名パッケージより優先します。シミュレータのルート検索は選択したトップと 到達可能な階層を使用し、未使用module内のインスタンス化で選択したルートを隠しません。 時間リテラルの整数・固定小数点表記では、 先頭ゼロを含めた数値を解釈します。interfaceの関数は、展開でモジュールに コピーされた後も、宣言元の時間スコープとコンパイル単位を使用します。 スカラーのinterfaceインスタンス・ポートへの問い合わせは、展開前にバインドされた interface型から解決します。generic interfaceポートとgenerate内のローカルハンドルも 対象です。child.infoのように子module内のinterfaceインスタンスを指定する スカラー階層も、インスタンスが展開で消える前に解決します。

Simulation は設計全体の時間精度（IEEE 1800-2023 3.14.3）で時刻を数えます。 既定は 1 ps で、run_until(1000) は 1 ns まで進めます。時間単位が 1 ns の モジュールの #10 は 10,000 ps 待ちます（3.14.1）。$time は呼び出した スコープの時間単位で表した時刻を整数に丸めて返し、半分は切り上げます（20.3.1）。 パッケージの関数ではそのパッケージの時間単位を使います。$stime はその値の 下位32ビットを返します（20.3.2）。組合せ回路は入力が変わったときに時刻を読み、 時刻だけが進んでも評価し直しません。時刻を持たない Simulator では0を返します。 $realtime は呼び出し元の時間単位で整数への丸めなしに real を返します（20.3.3）。 たとえば時間単位が1 nsのスコープで1.25 ns時点では、$realtime は1.25、 $time は1を返します。real は IEEE 754 倍精度のため、大きな時刻では 変換時に精度を失う場合があります。checkpoint の復元後は復元した時刻を参照します。

%t は時刻を設計全体で最も細かい時間精度の単位で、20 桁の欄に表示します（IEEE 1800-2023 20.4.3）。 `timescale 1ns/1ps のもとで #1.5 の後に $display("%0t", $realtime) を実行すると 1500 を表示します。 時間スケールのない設計は既定の 1 ns / 1 ps を使うため、%t はやはりピコ秒で表示します。 報告する時刻を持たない string の値に対する %t は拒否します。$timeformat には対応していません。

$printtimescale は IEEE1800-2023 20.4.2 の形式で時刻スコープを表示します。 例: Time scale of (Top.child) is 100ns / 10ps。 引数なしの現在スコープ、design element、$unit、$root を指定でき、 initial、always 系のプロセスとサブルーチンで実行できます。 現在のモジュールと相対参照には実際のインスタンス階層名を使い、 package・interface の手続きは宣言元の時間単位と精度を保持します。

乱数 ​

$urandom は周期が2の32乗の決定的な線形合同法を使います （IEEE 1800-2023 18.13.1、18.14）。同じシードで同じ列を再現し、 シード引数は変更しません。サブルーチン内では呼び出し元プロセスの列を使い、 乱数状態はチェックポイントの保存・復元に含まれます。 既定シードと具体的な乱数値は実装依存です。 組み合わせプロセスでは、プロセスの起動時にだけ乱数列が進みます。 always_comb は時刻0と暗黙の感度リストの入力変化時に実行され、 always @* は入力変化を待ちます。入力が変わらない再評価では乱数列は進みません。 定数値を要求する文脈では診断を返します。

$urandom_range(maxval, minval) は $urandom の列から両端を含む範囲の値を返し、 逆順の範囲は入れ替えます。minval の既定値は0です（18.13.2）。 $random は IEEE 1800-2023 附属書 N のアルゴリズムに従うため、 Icarus Verilog などそれを実装するシミュレータと同じ値を返します。 $random(seed) はシード変数を更新します。引数がなければプロセスごとのシードを 使い、その初期値は0です。そのため $random を呼ぶプロセスが1つだけの設計では、 設計全体で1つのシードを持つシミュレータと一致します。

実数の数学関数 ​

$ln、$log10、$exp、$sqrt、$pow、$floor、$ceil、$sin、 $cos、$tan、$asin、$acos、$atan、$atan2、$hypot、$sinh、 $cosh、$tanh、$asinh、$acosh、$atanh は real を引数と戻り値とし、 IEEE 1800-2023 20.8.2 の対応する C 数学関数に従います。整数と shortreal の引数は 呼び出し前に real に変換します。$floor と $ceil も real を返し、 $atan2(y, x) の引数順序を保持します。定義域や値域を超える場合は、対応する 浮動小数点の NaN や無限大を返します。

組み合わせ・クロック・時間付きプロセスで利用でき、引数が定数なら展開時に評価します （11.2.1）。入れ子の呼び出しと real パラメーターの精度を保持し、整数への代入や cast では 最終結果を変換します。すべてのシミュレーターバックエンドで同じ数学演算の評価処理を使います。

Veryl と SystemVerilog の混在 ​

Simulator::from_mixed_sourcesは両言語のソースを組み合わせます。トップはどちらの言語でもよく、 階層は Veryl → SV → Veryl のように言語境界を複数回跨げます。Veryl では $sv::Module、 SV からは Veryl のモジュールや interface を Veryl の emitter が出力する名前で参照します。 出力された SV に対して書いた SV コードがそのまま使えます。プロジェクト prj のモジュール Module は prj_Module、Veryl.toml で omit_project_prefix を設定した場合は Module です。 Veryl.toml がない場合のプロジェクト名は prj です。Veryl モジュールの出力名と同名の SV モジュールは 重複定義になります。Veryl のトップは Veryl の名前で指定します。数値パラメータは、それぞれの frontend が解決します。

interface と input / output modport のメンバー接続も双方向に対応します。SV の interface は Veryl で inst bus: $sv::Bus;、ポートで bus: modport $sv::Bus::slave と指定できます。 SV から Veryl の interface をインスタンス化し、両言語のモジュールに接続することもできます。 interface のパラメータ、インスタンス配列、SV の generic interface ポートは接続先の型で解決します。 Veryl からインスタンス化した SV interface の内部ロジックは、SV frontend で実行します。

パラメータの宣言幅が先行する interface パラメータに依存する場合も、SV側の名前付き上書きの順序にかかわらず、宣言順で上書きを反映します。 VerylとSVに同名のモジュールがある場合、$sv::Module はSV側の定義を選択します。 interface の既定値で呼び出す定数関数は、native analyzer が本体を式として表せる場合に宣言式へ展開します。 ループなど、本体を宣言式で表せないヘッダ依存の定数関数は、未対応として診断します。 引数型や戻り値型の幅がヘッダパラメータに依存する関数も、宣言式でその型変換を表せないため未対応として診断します。 宣言内のキャスト先のサイズがinterfaceパラメータに依存する場合や、定数関数をシンボリックに解析できない場合も、既定値で計算した結果を固定せず未対応として診断します。

両 frontend の宣言情報と解析結果を直接接続するため、Veryl の SV emitter は不要です。 言語境界を跨ぐ interface 関数の呼び出しと、関数の import / export modport は、まだ未対応です。 各言語内での対応範囲は従来どおりです。

DPI-C imports ​

sv-dpi Cargo feature は systemverilog を含み、import "DPI-C" による C 関数呼び出しを有効にします。 dpi_function または dpi_library で関数を登録します。どちらも C 側の型との一致を呼び出し側が保証する unsafe API です。

対応するのは、モジュール・package で宣言した関数を always_ff とそこから呼ぶ関数で使う場合です。 最大16個の input 引数を扱い、型は bit、logic、byte、shortint、int、longint（符号付き・符号なし）、戻り値はそれらか void です。 組み合わせ回路からの呼び出し、context、task import、export、output / inout、packed vector、real、string などは未対応です。

登録のコード例と詳細は英語版の DPI-C importsを参照してください。

Veryl が出力する SystemVerilog ​

Veryl の適合性スイートは、Veryl が出力する SystemVerilog に対しても実行します。対象外として 残るケースは次のとおりです。

  • 位置指定の要素と default: を混在させた配列リテラル（'{a, default: b}）に対して、Veryl は不正な SystemVerilog を出力します。
  • Celox の Veryl フロントエンドは、always_ff 内での出力引数や副作用を持つ関数呼び出しを オプトインで扱えますが、Veryl 自身はこれを拒否します。出力される SystemVerilog の呼び出し では、Veryl のノンブロッキングの意味ではなく即座にコピーアウトされてしまうためです。 こうしたデザインには対応する SystemVerilog がなく、出力されません。
  • テストベンチ用のモジュール（クロックや $finish のスケジューリングを伴う initial ブロック、階層代入）は、シミュレーション可能な SystemVerilog モジュールとして 出力されません。
