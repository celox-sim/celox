SystemVerilog サポート ​

Celox は Rust API から SystemVerilog をシミュレートできます。 ソースファイルとトップモジュールを指定して使います。 TypeScript パッケージと Vite プラグインは、現時点では Veryl のみを読み込みます。

Celox は IEEE Std 1800™-2023 に従います。 標準をなぞる代わりに、対応範囲と逸脱事項のページでは 未対応の機能、部分対応の機能（対応・未対応の対照表）、個別制約、 意図的な逸脱を分けて整理しています。 記載のない未対応・制限・逸脱に該当しない有効な IEEE 1800-2023 コードは標準どおりに動作します （見つからない差異は不具合として扱ってください）。既定モードでは既定警告付きの互換緩和をいくつか受理しますが、 strict モード（strict = true / --strict）で記載のない IEEE 1800-2023 外のコードを受け入れてしまう場合も不具合です。

最初のモジュールを動かす ​

Rust プロジェクトに Celox を追加します。

toml
[dependencies]
celox = "*"

Simulator::from_sv_sources にソース文字列とそのパスを渡し、トップモジュール名を指定します。

rust
use celox::Simulator;
use std::path::Path;

let source = r#"
    module Counter(input logic clk, input logic rst, output logic [7:0] q);
        always_ff @(posedge clk) q <= rst ? 8'd0 : q + 8'd1;
    endmodule
"#;
let mut sim = Simulator::from_sv_sources(
    vec![(source, Path::new("counter.sv"))],
    "Counter",
)
.build()?;

let clk = sim.event("clk");
let rst = sim.signal("rst");
let q = sim.signal("q");
sim.modify(|io| io.set(rst, 1u8))?;
sim.tick(clk)?; // カウンタをリセット。
sim.modify(|io| io.set(rst, 0u8))?;
sim.tick(clk)?; // 立ち上がりエッジを1回進める。
assert_eq!(sim.get(q), 1u8.into());

ファイルが複数ある場合は、同じリストに追加します。各ファイルは独立したコンパイル単位です。 トップには SystemVerilog のモジュール名を指定します。

デザインの動かし方を選ぶ ​

テストで行いたいことAPI
Rust から入力を設定し、論理を評価してクロックイベントを進めるSimulator::from_sv_sources
シミュレーション時刻を進め、時間を持つプロセスと final 手続きを実行するSimulation::from_sv_sources
Veryl と SystemVerilog のソースを一緒に扱うSimulator::from_mixed_sources

Simulator::tick は指定イベントの立ち上がりエッジを駆動します。 Simulation は時刻を管理し、スケジュールされたエッジを実行します。 Simulator はプロセスを実行しません。そのため、タイミング制御を持つプロセス、 定数でない initial ブロック、final 手続きを持つデザインには Simulation が必要です。 Simulator で構築すると SimulatorErrorKind::ProcessRequiresSimulation で失敗します。 どのプロセスに Simulation が必要かは 実行モデルを参照してください。

X/Z を扱う場合は builder に .four_state(true) を指定します。 状態モデルは 4 値シミュレーションを参照してください。 Veryl と混在する階層では Simulation::from_sources(veryl).with_sv_sources(sv) を使います。

対応概要と標準からの逸脱 ​

未対応の構文は、構文名と追跡 issue を含む Unsupported エラーで拒否します。 黙って無視することはありません。

区分概要詳細
未対応bind、checker、clocking ブロック、specify ブロック、UDP、ref ポート、disable fork 以外の disable、wait_order、unpacked / tagged union未対応の機能
部分対応ポート/ネット/defparam/ゲート、階層参照、interface、virtual interface、unpacked 構造体、手続き的 force/assign、遅延、イベント制御、クラス、ランダム化、動的コンテナ、並行アサーション、covergroup（カバーポイント、クロス、オプション、サンプリングイベントは未対応）、I/O の対応・未対応対照表部分対応の機能
個別制約non-ANSI ポート式、always_comb / always_latch 内のノンブロッキング代入、ループ展開上限などの個別の制限個別制約
標準準拠コードへの逸脱program 継続代入の実行領域、モジュール間 interface の static 記憶域、手続き的 assign の上書きタイミング、実行時 %p、$exit 警告など標準準拠コードに影響する逸脱
標準外コードの許容オプションや既定警告の緩和（strict = true / --strict でエラー化）および変数選択への force や $psprintf などの非標準拡張標準外コードの許容

Veryl と混在させる ​

どちらの言語もトップにでき、モジュール階層は双方向に言語境界を跨げます。 Simulator::from_mixed_sources に両言語のソースを渡します。 Veryl からは $sv::Module、SV からは prj_Module などの Veryl の出力名で参照します。 interface と input / output modport も言語間で接続できます。 Veryl と SystemVerilog の混在を参照してください。

DPI-C imports ​

手続きコードから C 関数を呼び出せます。 関数や共有ライブラリは dpi_function / dpi_library で登録します。 C と SV の型を一致させる必要があるため、どちらも unsafe API です。 celox run コマンドは --dpi-lib PATH で共有ライブラリをリンクします。 対応する型と呼び出し位置は DPI-C importsを参照してください。

個別の挙動を調べる ​

  • 未対応の機能
  • 部分対応の機能
  • 個別制約
  • 標準準拠コードに影響する逸脱
  • 標準外コードの許容
  • イベント実行順序の選択
  • 時間単位と精度の既定値
  • 乱数のシードと再現性
  • 終了処理と final 手続き
  • メモリファイル（$readmemh / $readmemb）

Veryl が出力する SystemVerilog ​

Veryl の適合性スイートは、Veryl が出力した SystemVerilog も検証します。 出力できないケースや言語間で意味が異なるケースは、残る対象外のケースを参照してください。
