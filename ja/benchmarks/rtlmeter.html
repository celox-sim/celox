RTLMeter ​

RTLMeter ダッシュボードで、Celox・Verilator・xezim の 2-state / 4-state 比較を確認できます。対象は固定した RTLMeter の XuanTie-E902 / E906 と HummingbirdV2-E203 の hello です。 E203 は上流の default 構成（フリップフロップの #1 遅延を含む）を使用し、 assertion を有効にした通常の共有変数の意味論で実行します。

測定値は、同じ VM・論理 CPU 上で順番を入れ替えて実行した 3 回の中央値です。 HDL の読み込みからコンパイル、起動、実行完了までを含みます。Verilator には C++ のビルド時間も含め、毎回新しいビルド先を使います。短いプログラムの 開発時の待ち時間を比較するもので、定常実行のスループットではありません。

Celox は celox run --backend tiered --jit hotspot で実行します。インタプリタですぐに シミュレーションを始め、頻繁に実行されるグループはバックグラウンドのコンパイルが終わり次第 ネイティブコードへ切り替えます。以前の値は設計全体をコンパイルしてから実行する native バックエンドで測定していたため、履歴との比較ではこの違いに注意してください。

2-state と 4-state は別のグラフにします。Verilator 5.052 の 4-state は実験的機能で、 X/Z の事前確認に通った場合だけ測定します。xezim は Nix で安定版リリースを固定し、 通常の 4-state VM を使用します。全体を 2-state にするモードはないため、2-state は 未対応と表示します。ゼロ初期化を 2-state の代用にはしません。

成功出力・終了コード・最終クロック数と、1 クロックで止める負の対照実験を検証します。 未対応・失敗・タイムアウトは表に表示し、性能値には加えません。毎日 04:37 UTC と 手動実行で比較し、master の結果を掲載します。生ログは 30 日間保存します。

コールドスタート時間に加えて、定常実行スループットを CoreMark（XuanTie-E902 / E906）で 測定する rtlmeter-steady-state-v1 も定期実行（毎日 05:17 UTC）しています。 コンパイル時間を除外した純粋なシミュレーション実行時間およびクロックスループット（cycles/sec、kHz）を 測定します。

固定リビジョン、ツール設定、実行例は英語の測定仕様を参照してください。
