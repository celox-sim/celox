passOverrides? ​

optional passOverrides?: string[]

Defined in: packages/celox/src/types.ts:411

Per-pass overrides applied on top of optLevel. Each entry: "+sir:<pass_name>" to enable, "-sir:<pass_name>" to disable.

Valid SIR passes: store_load_forwarding, hoist_common_branch_loads, bit_extract_peephole, optimize_blocks, split_wide_commits, commit_sinking, inline_commit_forwarding, eliminate_dead_working_stores, reschedule, coalesce_stores, gvn, concat_folding, xor_chain_folding, vectorize_concat, split_coalesced_stores, partial_forward, identity_store_bypass, if_conversion (small pure if/else diamonds of clocked processes become muxes), tail_call_split, derived_edge_units (generated units for the edges of gated and divided clocks; "-sir:derived_edge_units" walks their plans instead, which builds faster and ticks slower), partitioned_settle (settle only the partitions of the combinational logic whose inputs changed; off unless enabled with "+sir:partitioned_settle"), net_inlining (SystemVerilog designs built with a dead store policy: combinational nets the policy does not keep observable become part of the logic that reads them)

Example ​

ts
["-sir:reschedule", "+sir:gvn"]

Defined in: packages/celox/src/types.ts:468

Simulation threads, including the calling thread. Default: 1.

With more than one thread, phases with enough independent work get lane-partitioned alternatives that run concurrently; each is kept only when it measures faster than its sequential version. Results are identical to sequential simulation. Use at most the number of physical cores.

Defined in: packages/celox/src/types.ts:479

Run tiered: execution starts on the interpreter immediately while the host's compiled tier is prepared on a background thread, and the simulation adopts it at the next safe point after compilation. Default: false (compile up front before the first tick).
