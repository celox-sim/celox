Circuit benchmark collection ​

The main dashboard measures complete hardware workloads. API calls, counters, and standard-library microbenchmarks remain available in the diagnostic dashboard.

Heliodor retains its existing comparison suite. rica uses scripts/run-rica-bench.sh with a Veryl TB and publishes Celox tiered / Veryl simulator tiered comparisons in the rica dashboard tab. The rica Benchmark workflow runs daily at 04:47 UTC or by manual dispatch. It runs all five pinned ELF kernels (tasks, syscalls, atomics, user and supervisor) on one host. Each point is the median total process time of three fresh runs, including compilation, board memory, stimulus and assertions. Publication requires successful mailbox negative controls, matching cycles and commits across both simulators, and all five complete kernel pairs. Source or workload changes start new charts; different architectures and host CPUs remain separate. tarunes has no accepted performance samples yet. Its synthetic-ROM qualification probe agrees with Verilator, including HDMI RGB, but still needs a fixed measurement recipe and collection runner. The paired Veryl/SV probes and reproduction instructions live in benchmarks/tarunes/. The collection does not combine these designs into an overall score.

Reproduce the representative circuits ​

The machine-readable selection, source revisions, testbench provenance and workload recipes are in benchmarks/collection.json. The logikbench Veryl port is pinned to 6179df1cd15e13600a36621fc6b57de521a93d9f.

sh
cargo build --release --locked -p celox --bin celox
cargo build --release --locked -p celox-bench --bin veryl-heliodor
node scripts/benchmark-collection.mjs list
node scripts/benchmark-collection.mjs prepare all work/circuits/sources
node scripts/benchmark-collection.mjs qualify all work/circuits/sources work/circuits/qualification
node scripts/benchmark-collection.mjs measure all work/circuits/sources work/circuits/measurement

all selects implemented collection runners; list also shows existing standalone runners and pending candidates. A comma-separated selection such as sha256,fft is supported. Use a fresh output directory for each invocation. The last two optional arguments to qualify or measure select prebuilt Celox and Veryl simulator binaries; defaults are target/release/celox and target/release/veryl-heliodor. The latter runner uses the Veryl 0.22.0 simulator library and also serves Heliodor. Debug runs are useful for validation, not release comparisons. The tool does not build Cargo projects or create target/ itself.

Each run verifies the pinned checkout and materializes tracked project bytes in a separate directory. The originals stay unchanged. It first executes the upstream self-checking TB, then corrupts an expected result in a separate working copy and requires an assertion failure. Exit zero alone is insufficient. A compile error, timeout, signal, missing timing record or incomplete workload cannot become a performance sample. Qualification timings are never published.

Measurement repeats each complete upstream scenario inside one simulation:

  • SHA-256: 4,096 pairs of the abc and empty-message known-answer tests.
  • FFT: 1,024 groups of the DC, Nyquist and bin-16 exact fixed-point tests.
  • LZ77: 16 groups of the periodic, small-alphabet and LFSR streams. Each phase stops once its expected byte count is received; the original cycle limit and every byte comparison remain. This avoids measuring the smoke TB's idle tail.

Resets, stimulus and assertions are included in execution time. Every measured process must complete the entire fixed workload and print its completion marker. Each simulator runs three fresh processes sequentially on the same host. The primary comparison is Celox tiered versus Veryl simulator tiered, with the same DUT and TB bytes. Celox lowers both DUT and TB to the shared SIR pipeline, starts execution in its interpreter and promotes to native code (O2). Veryl starts in Cranelift with asynchronous C compilation enabled. Completing before promotion is valid; dispatch/promotion statistics are retained. Both use one simulation thread; compiler parallelism follows each implementation's defaults within the same host CPU allocation.

The dashboard's total is the median process wall time, from launching the runner through its exit, including startup and shutdown. CLI binary builds and source preparation happen before measurement. The internal compilation/startup and execution intervals remain in diagnostic logs and are not published as comparison charts: background compilation overlaps execution, so those intervals do not represent isolated compiler cost or warmed throughput. Every process gets a new empty Veryl AOT cache; Celox's build cache and waveform output are disabled. This cold-tiered-process-v1 contract starts new charts, separate from the old native-only internal-timing series.

Remaining background C compiler processes are stopped after their runner exits, before the next sample starts. Ambient Celox/Veryl tuning environment variables are cleared so they cannot silently change the comparison settings.

Both simulators must pass the positive test and reject its broken oracle. Publication requires a complete pair with identical source/TB hashes, three successful samples per simulator, valid tiered statistics and completion markers.

results.json retains the source revision and content hash, TB hash, work count, frontend, backend, state model, optimization level, thread count, host CPU and architecture, both runner binary hashes, logs, and individual samples. A changed source, TB or workload contract starts a new chart. The Circuit benchmarks workflow runs daily at 04:17 UTC and on manual dispatch. Only successful scheduled/manual runs on master publish history; failed logs are retained as artifacts.

SystemVerilog frontend phase ​

A circuit, its stimulus/testbench, its source frontend and its execution backend are separate identities. A Verilator run over emitted SV does not itself test Celox's SV frontend. Future comparisons should use one pinned SV DUT/TB set for both Celox SV and Verilator, and retain equivalent reset, seed, completion and output-check contracts.

The catalog records existing upstream SV TB paths now, including the original logikbench repository pinned to e8c7c4388c66302c6adb235678512ce62b79968a:

  • logikbench/benchmarks/{blocks/sha256,blocks/fft,large/lz77}/testbench/ contains the original self-checking Verilog TBs. Some report FAILED and still call $finish; adapters must require PASSED and reject failures explicitly.
  • The Veryl port's equiv/equiv_tb.v files instantiate both the original Verilog and the emitted SV DUT. They are equivalence checks, not single-DUT performance measurements.
  • The original and ported FFT/SHA TBs do not use identical inputs or oracles. Their results must not be joined as a frontend-only comparison without a common workload contract.
  • tarunes has src/tb_top.sv, but it merely prints PC after a fixed delay and enables waveform dumping. It needs a completion/output oracle before adoption as a published performance workload.

The candidate selection is based on circuit diversity, before measuring speed. An unsupported or incorrect run remains a visible qualification issue, never a zero-time result or an omitted slow sample.
